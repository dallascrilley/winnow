### Dev-environment mechanics learned (needed by every future unit)
- [hand] Root `.env` (gitignored): `BETTER_AUTH_SECRET`, `APP_URL`/`BETTER_AUTH_URL=http://127.0.0.1:8080`, `WORKSPACE_ORG_NAME/DOMAIN/OWNER_EMAIL`, `A2A_SECRET`, `DISPATCH_DEFAULT_OWNER_EMAIL` (the last two matter for U5)
- Email sign-up is disabled by design; dev auth = one-shot auto-dev-account (`dev@local.test`) created on first HTML GET, only if no user rows exist. It will never re-fire once the account exists (wipe the app's `data/app.db*` to redo).
- The auto-created session token lands in the framework `sessions` table (not better-auth's `session` table). Scripted API access: `Cookie: an_session_workspace=<token from sessions table>` passes the auth guard (cookie name comes from workspace mode; see core `cookie-namespace.js`).
- The `pnpm action` CLI auto-binds `dev@local.test` and creates that user row as a side effect — keep CLI-first flows in mind before relying on the HTTP auto-create.
- Org context auto-resolves once `WORKSPACE_ORG_*` env is set (connection save returned the org id automatically).

### Review-pass fix (2026-07-17) — CLI identity mismatch on list actions
- [bug] Fresh-eyes review found `pnpm action list-*` returned empty on every DB while creates worked. Root cause: two identity resolvers disagreed — the script runner's dev-session binds the user from the app's `sessions` table (empty on a fresh PG DB → anonymous → `accessFilter` hides all rows), while the scheduling context fell back to `dev@local.test`. Creates used the scheduling resolver (worked); reads used core's access filter (empty).
- [fix] `AGENT_USER_EMAIL=dev@local.test` added to `apps/scheduler/.env` — the framework's documented explicit override, honored by BOTH resolvers (dev-session.js returns it unchanged). Required local env for fresh clones: `DATABASE_URL`, `AGENT_USER_EMAIL` (both gitignored; production gets real sessions). NOTE for U8: document these in the app README env section.
- [hand] Comment hardening: `actions/run.ts` documents the load-bearing import order (`@agent-native/core/scripts` evaluates `loadEnv()` → `.env` → dialect selection); both `drizzle*.config.ts` files document the DATABASE_URL regeneration trap (wrong dialect env silently yields "0 tables").
- [cmd] Re-validation: `pnpm typecheck` clean; `pnpm action list-event-types` / `list-bookings` (no env prefix) return the PG rows; oxfmt applied to all touched files.
