### Dev-environment mechanics learned (needed by every future unit)
- [hand] Root `.env` (gitignored): `BETTER_AUTH_SECRET`, `APP_URL`/`BETTER_AUTH_URL=http://127.0.0.1:8080`, `WORKSPACE_ORG_NAME/DOMAIN/OWNER_EMAIL`, `A2A_SECRET`, `DISPATCH_DEFAULT_OWNER_EMAIL` (the last two matter for U5)
- Email sign-up is disabled by design; dev auth = one-shot auto-dev-account (`dev@local.test`) created on first HTML GET, only if no user rows exist. It will never re-fire once the account exists (wipe the app's `data/app.db*` to redo).
- The auto-created session token lands in the framework `sessions` table (not better-auth's `session` table). Scripted API access: `Cookie: an_session_workspace=<token from sessions table>` passes the auth guard (cookie name comes from workspace mode; see core `cookie-namespace.js`).
- The `pnpm action` CLI auto-binds `dev@local.test` and creates that user row as a side effect — keep CLI-first flows in mind before relying on the HTTP auto-create.
- Org context auto-resolves once `WORKSPACE_ORG_*` env is set (connection save returned the org id automatically).

- [finding] Run 1 (unpinned sampling): 70.8% (17/24), all 5 mid cases failed low. Root cause: ollama's default temperature made borderline scores non-deterministic — the same near-verbatim input scored 0.55 live and <0.4 in eval. Fix: `options: { temperature: 0 }` in callOllama — deterministic decoding is correct for a scoring workload (same lead twice → same score).
- [finding] Run 2 (temp 0): 75% — failure pattern flipped: free-email mid cases over-promoted to auto-route (>=0.8). The eval caught a real routing-policy gap: free-address "just researching" leads would auto-book AE time.
- [fix] Run 3 (temp 0 + tightened PROMPT_RULES + two wrong goldens corrected): 87.5% (21/24). New rules: free-email trust discount (<0.80 without specific immediate intent + authority), segment-describes-company, gibberish policy. mid/free-email tags 5/5.
- [fix] Run 4 (+ vendor-pitch rule "a pitch to resell our product is not intent to buy it", goldens made consistent with the segment rule): **95.8% (23/24)**. vendor + adversarial tags 2/2 and 3/3. Run 4 also self-emitted `eval_completed` (emission code live). Residual miss: ec_etsy_shop medium-vs-low (1-person craft shop parks for human review instead of auto-disqualify — operationally harmless, the gate catches it; left as a visible, honest miss rather than overfitting the prompt to the suite). Full progression: 70.8% → 75% → 87.5% → 95.8% across four runs, each move attributable to a specific promptHash/config change.
- [note] Golden edits are only ever made when the GOLDEN is wrong (contradicts the written scoring policy or the ICP), never to fit the model — each relabel is justified inline in eval-cases.ts.
